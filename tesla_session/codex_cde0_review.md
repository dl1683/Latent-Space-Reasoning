1. **Plurality analysis is directionally sound, but not yet statistically clean.** The core mechanism is plausible: correct answers cluster while wrong answers spread. The traps are: `N=25` is small, the selector was discovered post hoc, ties can materially affect results, answer extraction/normalization may introduce hidden degrees of freedom, and accuracy needs paired uncertainty estimates against baseline/random, not just point estimates. Report bootstrap or exact paired CIs, tie policy, normalized answer tables, and per-task vote margins.

2. **Section 8 mostly holds up, with narrower claims.** The strong version is: “On arithmetic with extractable answers, prefix perturbation creates answer-level diversity, and plurality converts some minority-correct cases into wins.” Avoid saying this proves general CDE selection. Also soften “strict oracle superset” and “model lacks capability”: those are statements about this sampled operator budget, not inherent capability.

3. **Phase 1A is the right next experiment as a pilot.** Greedy vs prefix vs temperature is exactly the right comparison. But pre-register selectors before running: plurality, verifier, random-pick, oracle; fixed extraction; fixed tie-breaking; matched sample budget; same tasks across operators. Include DeepSeek if cheap, but the experiment should primarily answer whether prefix beats ordinary temperature self-consistency at answer-level diversity.

4. **What’s missing:** raw per-task answer histograms; tie cases; confidence intervals; paired tests; extraction failure rates; normalization rules; answer entropy / max wrong-cluster metrics; plurality margin distributions; sensitivity to `N`; held-out validation tasks; and a non-arithmetic selector plan. Legal remains only an oracle-gap observation, not evidence that CDE is deployable there.

5. **GO, but only as exploratory implementation / Phase 1A pilot.** Do not treat the 72% / 56% as paper-ready confirmatory results yet. The finding is strong enough to implement the pipeline and spend GPU time, but the next run must be locked down statistically so the plurality result survives outside the dataset where it was discovered.
