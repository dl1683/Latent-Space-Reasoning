**Executive Verdict**
Wave 2 does not overturn the Wave 1 directive. It reinforces it.

Most Wave 2 proposals are not standalone architectures; they are candidate-generation operators, selector upgrades, or measurement probes that should live inside a **Controlled Decorrelation Ensemble**. The central question remains:

> Which interventions produce candidates whose errors are less correlated under equal compute, and can a realistic selector exploit that diversity?

Claude’s “Three Pillars” taxonomy is useful as a map, but it is not yet an architecture. It is missing the control layer: measurement, allocation, routing, and stopping.

**2. Cross-Domain Ensemble Challenge**

Architectures that can produce **real decorrelation**:

- **Strongest:** #13 ALM, because it explicitly measures and avoids duplicate trajectory basins.
- **Strong but domain-limited:** #14 Neuro-Symbolic, if independent formalization errors exist.
- **Conditional:** #9 DDC, if alternative decompositions produce different error modes.
- **Conditional:** #10 RARS, if elicited facts differ and are actually relevant.
- **Conditional/high-risk:** #11 CIR and #16 Attention Surgery, if their mechanisms are validated.
- **Weak:** #8 GGIO, because multi-start optimization toward the same proxy may collapse into the same wrong basin.

Architectures that mostly add **entropy without useful diversity**:

- #8 with self-certainty objectives.
- #10 when it generates unverified facts.
- #12 when critics invent issues.
- #16 when attention configs are not causally tied to correctness.
- #17 when previous attempts contaminate later attempts.
- #15 does not generate diversity at all.

Architectures that mainly improve **selector quality** rather than candidate quality:

- **#14** via symbolic execution.
- **#15** via learned reranking, if calibrated.
- **#9** via subproblem majority/confidence.
- **#10** via fact cross-verification, weakly.
- **#12/#17** only if critique/refinement acts as a selector, which is doubtful for 4B Q4.

Architectures that mainly improve **candidate quality**:

- #9 DDC by simplifying the problem.
- #10 RARS by adding explicit context.
- #14 Neuro-Symbolic by moving computation to tools.
- #11/#16 if mechanism-targeted steering is real.
- #8 only with a valid objective.

**3. Wave 1 + Wave 2 Integration**

The Three Pillars hold up as a **taxonomy**, not as a system design.

They align with Controlled Decorrelation Ensemble only if reframed:

- Diversification = candidate/operator portfolio.
- Quality assessment = selector/verifier stack.
- Iterative refinement = one class of candidate operator, not a separate architectural pillar.
- Missing layer = measurement, allocation, calibration, and routing.

The mistake in the Wave 2 synthesis is “pick one from each pillar.” That is not how ensembles win. Ensembles win by measured complementarity: marginal accuracy, pairwise error correlation, selector reliability, and compute-normalized lift.

Unified top-5 across all 17, ranked for current project value:

1. **#5 Controlled Decorrelation Ensemble**: still the backbone. Everything else plugs into it.
2. **#13 Attractor Landscape Mapping**: best Wave 2 contribution because it directly supports decorrelation measurement and duplicate-basin suppression.
3. **#9 Decompose-Dispatch-Compose**: most practical structural candidate-quality improvement.
4. **#14 Neuro-Symbolic Hybrid**: strongest exact-verifier path for arithmetic/logic, though domain-limited.
5. **#11 Causal Intervention Reasoning**: highest mechanistic upside, but only after measurement proves where random perturbation helps.

Near misses: #10 RARS for legal/knowledge tasks, #4 Inverse Speculative for externally guided improvement, #16 only after attention-sink evidence.

**4. Meta-Architecture Challenge**

Claude’s decomposition is close but incomplete.

The right decomposition is:

1. **Operator Portfolio**: prefix, temperature, prompt variants, decomposition, tools, retrieval, steering.
2. **Diversity Control**: trajectory fingerprints, answer clusters, basin coverage, duplicate suppression.
3. **Selection / Verification**: exact checker, symbolic executor, majority, learned scorer, abstention.
4. **Compute Allocation**: which operator gets more samples, when to stop, when to branch.
5. **Refinement / Repair**: optional loop, treated as another operator, not the governing frame.

The missing pillar is **control measurement**: a contract for proving that an operator adds useful, selectable, decorrelated candidates.

Controlled Decorrelation Ensemble subsumes the Three Pillars. It does not sit alongside them. It is the architecture; the pillars are component categories inside it.

**5. Missing Critical Architectures**

Claude is still avoiding the most important architecture: **adaptive, measurement-driven operator allocation**.

Missing designs:

- **Diversity-Optimized Best-of-N**: choose candidate operators by measured error correlation, not intuition.
- **Early-Trajectory Router**: generate 32-64 tokens, fingerprint the trajectory, expand only novel/promising basins.
- **Verifier-First Regeneration**: for arithmetic/code, verify intermediate spans and regenerate only failed spans.
- **Disagreement-Constrained Decoding**: reject candidates whose answer/trajectory signature duplicates existing candidates.
- **Selector Calibration System**: explicitly measure selector false positives, false negatives, and oracle-selector gap.
- **True External Retrieval/Tools**: RARS uses the model as its own database; for legal/factual tasks, that avoids the real RAG problem instead of solving it.

The systematic blind spot is measurement discipline. Claude keeps proposing new intervention surfaces before proving which surfaces decorrelate errors.

**6. Priority Directive**

Develop **Architecture 5 redesigned as Controlled Decorrelation Ensemble**.

The next document should be:

**“Controlled Decorrelation Ensemble v1: Measurement Contract, Operator Portfolio, and Selector Protocol.”**

It should specify:

- Candidate operators: baseline greedy, temperature, prefix perturbation, prompt paraphrase, DDC, ALM-guided seed selection, neuro-symbolic for computable tasks, RARS for knowledge tasks.
- Equal-budget comparisons: same token budget, same wall-clock budget, same N curves.
- Trace schema: prompt, operator, seed, first-32-token fingerprint, hidden/embedding fingerprint if available, extracted answer, final answer, verifier result.
- Metrics: marginal accuracy, oracle accuracy, selected accuracy, pairwise error correlation, duplicate-basin rate, selector false-positive rate, cost-normalized lift.
- Routing: which operators apply to arithmetic, legal, planning, logic/code.
- Stopping rules: stop when new candidates duplicate existing basins or selector confidence saturates.

Evidence required before implementation:

1. Prefix vs temperature vs prompt paraphrase vs random baseline under equal compute.
2. Pairwise error-correlation matrix across operators.
3. Oracle-selector gap: `any candidate correct` vs `system selected correct`.
4. First-32-token or hidden-state clustering correlation with correctness.
5. N-scaling curves: N=1, 2, 4, 8, 16 under equal budgets.
6. Domain split: arithmetic, legal, planning, logic/code separately.
7. For #13: proof that basin clusters are stable enough to guide sampling.
8. For #11/#16: mechanism probes before intervention work.
9. For #14: formalization error rate and majority-wrong rate.
10. For #10: fact hallucination rate and whether elicited facts improve held-out legal answers.

Bottom line: do not build CIR, IDR, EBRL, or Attention Surgery as the next system. Build the **measurement-governed ensemble architecture** that can decide, empirically, which of those operators deserves to **Executive Verdict**
Wave 2 does not overturn the Wave 1 directive. It reinforces it.

Most Wave 2 proposals are not standalone architectures; they are candidate-generation operators, selector upgrades, or measurement probes that should live inside a **Controlled Decorrelation Ensemble**. The central question remains:

> Which interventions produce candidates whose errors are less correlated under equal compute, and can a realistic selector exploit that diversity?

Claude’s “Three Pillars” taxonomy is useful as a map, but it is not yet an architecture. It is missing the control layer: measurement, allocation, routing, and stopping.

**2. Cross-Domain Ensemble Challenge**

Architectures that can produce **real decorrelation**:

- **Strongest:** #13 ALM, because it explicitly measures and avoids duplicate trajectory basins.
- **Strong but domain-limited:** #14 Neuro-Symbolic, if independent formalization errors exist.
- **Conditional:** #9 DDC, if alternative decompositions produce different error modes.
- **Conditional:** #10 RARS, if elicited facts differ and are actually relevant.
- **Conditional/high-risk:** #11 CIR and #16 Attention Surgery, if their mechanisms are validated.
- **Weak:** #8 GGIO, because multi-start optimization toward the same proxy may collapse into the same wrong basin.

Architectures that mostly add **entropy without useful diversity**:

- #8 with self-certainty objectives.
- #10 when it generates unverified facts.
- #12 when critics invent issues.
- #16 when attention configs are not causally tied to correctness.
- #17 when previous attempts contaminate later attempts.
- #15 does not generate diversity at all.

Architectures that mainly improve **selector quality** rather than candidate quality:

- **#14** via symbolic execution.
- **#15** via learned reranking, if calibrated.
- **#9** via subproblem majority/confidence.
- **#10** via fact cross-verification, weakly.
- **#12/#17** only if critique/refinement acts as a selector, which is doubtful for 4B Q4.

Architectures that mainly improve **candidate quality**:

- #9 DDC by simplifying the problem.
- #10 RARS by adding explicit context.
- #14 Neuro-Symbolic by moving computation to tools.
- #11/#16 if mechanism-targeted steering is real.
- #8 only with a valid objective.

**3. Wave 1 + Wave 2 Integration**

The Three Pillars hold up as a **taxonomy**, not as a system design.

They align with Controlled Decorrelation Ensemble only if reframed:

- Diversification = candidate/operator portfolio.
- Quality assessment = selector/verifier stack.
- Iterative refinement = one class of candidate operator, not a separate architectural pillar.
- Missing layer = measurement, allocation, calibration, and routing.

The mistake in the Wave 2 synthesis is “pick one from each pillar.” That is not how ensembles win. Ensembles win by measured complementarity: marginal accuracy, pairwise error correlation, selector reliability, and compute-normalized lift.

Unified top-5 across all 17, ranked for current project value:

1. **#5 Controlled Decorrelation Ensemble**: still the backbone. Everything else plugs into it.
2. **#13 Attractor Landscape Mapping**: best Wave 2 contribution because it directly supports decorrelation measurement and duplicate-basin suppression.
3. **#9 Decompose-Dispatch-Compose**: most practical structural candidate-quality improvement.
4. **#14 Neuro-Symbolic Hybrid**: strongest exact-verifier path for arithmetic/logic, though domain-limited.
5. **#11 Causal Intervention Reasoning**: highest mechanistic upside, but only after measurement proves where random perturbation helps.

Near misses: #10 RARS for legal/knowledge tasks, #4 Inverse Speculative for externally guided improvement, #16 only after attention-sink evidence.

**4. Meta-Architecture Challenge**

Claude’s decomposition is close but incomplete.

The right decomposition is:

1. **Operator Portfolio**: prefix, temperature, prompt variants, decomposition, tools, retrieval, steering.
2. **Diversity Control**: trajectory fingerprints, answer clusters, basin coverage, duplicate suppression.
3. **Selection / Verification**: exact checker, symbolic executor, majority, learned scorer, abstention.
4. **Compute Allocation**: which operator gets more samples, when to stop, when to branch.
5. **Refinement / Repair**: optional loop, treated as another operator, not the governing frame.

The missing pillar is **control measurement**: a contract for proving that an operator adds useful, selectable, decorrelated candidates.

Controlled Decorrelation Ensemble subsumes the Three Pillars. It does not sit alongside them. It is the architecture; the pillars are component categories inside it.

**5. Missing Critical Architectures**

Claude is still avoiding the most important architecture: **adaptive, measurement-driven operator allocation**.

Missing designs:

- **Diversity-Optimized Best-of-N**: choose candidate operators by measured error correlation, not intuition.
- **Early-Trajectory Router**: generate 32-64 tokens, fingerprint the trajectory, expand only novel/promising basins.
- **Verifier-First Regeneration**: for arithmetic/code, verify intermediate spans and regenerate only failed spans.
- **Disagreement-Constrained Decoding**: reject candidates whose answer/trajectory signature duplicates existing candidates.
- **Selector Calibration System**: explicitly measure selector false positives, false negatives, and oracle-selector gap.
- **True External Retrieval/Tools**: RARS uses the model as its own database; for legal/factual tasks, that avoids the real RAG problem instead of solving it.

The systematic blind spot is measurement discipline. Claude keeps proposing new intervention surfaces before proving which surfaces decorrelate errors.

**6. Priority Directive**

Develop **Architecture 5 redesigned as Controlled Decorrelation Ensemble**.

The next document should be:

**“Controlled Decorrelation Ensemble v1: Measurement Contract, Operator Portfolio, and Selector Protocol.”**

It should specify:

- Candidate operators: baseline greedy, temperature, prefix perturbation, prompt paraphrase, DDC, ALM-guided seed selection, neuro-symbolic for computable tasks, RARS for knowledge tasks.
- Equal-budget comparisons: same token budget, same wall-clock budget, same N curves.
- Trace schema: prompt, operator, seed, first-32-token fingerprint, hidden/embedding fingerprint if available, extracted answer, final answer, verifier result.
- Metrics: marginal accuracy, oracle accuracy, selected accuracy, pairwise error correlation, duplicate-basin rate, selector false-positive rate, cost-normalized lift.
- Routing: which operators apply to arithmetic, legal, planning, logic/code.
- Stopping rules: stop when new candidates duplicate existing basins or selector confidence saturates.

Evidence required before implementation:

1. Prefix vs temperature vs prompt paraphrase vs random baseline under equal compute.
2. Pairwise error-correlation matrix across operators.
3. Oracle-selector gap: `any candidate correct` vs `system selected correct`.
4. First-32-token or hidden-state clustering correlation with correctness.
5. N-scaling curves: N=1, 2, 4, 8, 16 under equal budgets.
6. Domain split: arithmetic, legal, planning, logic/code separately.
7. For #13: proof that basin clusters are stable enough to guide sampling.
8. For #11/#16: mechanism probes before intervention work.
9. For #14: formalization error rate and majority-wrong rate.
10. For #10: fact hallucination rate and whether elicited facts improve held-out legal answers.

Bottom line: do not build CIR, IDR, EBRL, or Attention Surgery as the next system. Build the **measurement-governed ensemble architecture** that can decide, empirically, which of those operators deserves to exist.
