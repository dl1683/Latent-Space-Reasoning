# Typed CLASS/COMPARE Admission Gate

**Date:** 2026-07-14  
**Role:** Work-loop Batch 9, Unit 1  
**Status:** **HEURISTIC / PROGRAM INFRASTRUCTURE.** This is a calibrated decision
procedure for admitting class research and adjudicating comparative claims. It is
not a founding class, a CAN theorem, a CANNOT theorem, or a mission result.

## 0. Registration and precommit before calibration

**Binding task - HEURISTIC.** Freeze one row-independent decision procedure that
distinguishes a forced computational class boundary from vocabulary or cost fiat,
while retaining the full symmetric-closure audit for every comparative or
"beats" claim.

**Claim discipline.** Unless a stronger label is attached, every calibration,
historical, occupation, and gate judgment in this file is **HEURISTIC**. A cited
repository result retains its own stronger or weaker label; this file does not
promote it. Normative definitions and frozen tokens are marked **FROZEN** rather
than presented as theorems.

**Precommitted return tokens - FROZEN.**

- **`CONFIRM`:** every calibration row receives its predeclared expected
  disposition from the single frozen procedure, without adding a row-specific
  predicate or changing the order of tests.
- **`KILL/AMEND`:** any historical winner is falsely killed, any adversarial
  negative falsely passes, or any graveyard case loses its exact binding death.
  The return must name the exact failing clause. The procedure may then be amended,
  but the failed version and reason remain in section 1 and the entire matrix must
  be rerun from the top.
- **`VOID`:** a row, expected disposition, antecedent, comparator, theorem packet,
  or resource contract is changed after its result is known; or the gate is used
  as the program's founding result.

**Execution precommit - EMPIRICAL.** Calibration is analytic and source-backed.
It uses no numerical experiment, no GPU, no subagent, and no edit to
`research/QUESTIONS.md`.

## 2. Frozen input packet and claim router

### 2.1 Required packet

For a proposed candidate `M`, the registrar must supply the following finite
packet before the gate is run. These are **FROZEN INPUT FIELDS**, not optional
persuasive prose.

1. **Antecedent packet:** an antecedent task or phenomenon `A`, stated in the
   vocabulary of an independent practice before candidate vocabulary or costs;
   extensional success/failure observations `O`; and two independently standard,
   non-isomorphic presentations `P1,P2` of the phenomenon.
2. **Boundary packet:** computational objects, morphisms/steps, admitted operations,
   uniformity, finite encodings, error semantics, composition and feedback laws,
   observation maps, resources and their preorder, free operations, and encoding
   equivalence.
3. **Erasure packet:** a uniform candidate-vocabulary erasure `E`, and an explicit
   statement of which objects, morphisms, observations, or composition laws cease
   to be preserved after erasure.
4. **Theorem packet:** one automatic useful CAN; one non-tautological CANNOT; one of
   the accepted architectures (canonicalization/duality, exact characterization or
   completeness, hierarchy/tradeoff, or universal simulation plus boundary); and a
   canonical or complete problem when the architecture requires one.
5. **Occupation packet:** the strongest typed translations to established fields,
   including objects, morphisms, observations, composition, resources, and the
   proposed theorem pair in both directions where available.
6. **Comparison packet, when applicable:** both frozen class contracts, the common
   task/interface/error contract, the claimed resource region, every operation
   declared common/free, all preprocessing/advice/calibration/conversion costs, and
   the proposed uniform task-preserving compiler.

**Missing-packet disposition - FROZEN.** Missing finite/uniform semantics returns
the relevant leak token in step C0 below. Missing antecedent or erasure evidence
returns `BOUNDARY-FIAT` in step C3. Missing theorem or occupation evidence returns
the corresponding readiness token in steps C4-C5. Absence of a literature result
is never evidence of novelty.

### 2.2 Claim router

**Router - FROZEN.**

- A definition or theorem about the internal objects, morphisms, observations, or
  limits of one proposed class runs `CLASS`.
- Any assertion that one class, implementation, substrate, representation, or
  mechanism beats, separates from, saves a resource against, dominates, or has a
  Pareto advantage over another runs `COMPARE`, even if the same artifact also runs
  `CLASS`.
- If both kinds occur, both procedures run. A `CLASS-CHANGE` return never immunizes
  the comparative assertion from `COMPARE`.

## 3. Version 2: the frozen decision procedure

### 3.1 `CLASS` procedure

Run C0-C6 in order. The first binding kill is the disposition; later applicable
tokens are recorded as corroboration. This order is **FROZEN**.

**C0 - finitary, uniform, and infinity-leak audit.** Verify finite descriptions,
uniform family generation, finite charged observations, finite precision/noise
semantics where relevant, finite advice/certificates, and ordinary finite-time
access to every primitive. Return `INFINITY-LEAK`, `UNBOUNDED-ADVICE`,
`UNCOMPUTABLE-QUOTIENT`, or `ORACLE-FIAT` if the corresponding power enters without
being a finite charged input. A finite computable subroutine merely declared free
continues to C1-C3; it is not misclassified as an uncomputable oracle.

**C1 - relabelling test.** Apply the uniform erasure `E`. If `E` is an
isomorphism on the computational objects and morphisms, preserves the observations
and composition laws, and only removes candidate-authored tags, colors, type names,
or wrappers, return **`RELABELLING-FIAT`**. A nontrivial task codomain alone does not
escape this test when erasure leaves all extensional behavior unchanged.

**C2 - resource-reindexing test.** Ask whether there is one computable monotone map
`f` from an already admitted resource preorder to the proposed resource preorder
such that, uniformly over all instances and machines, the new cost is `f` of the
old cost and every proposed CAN/CANNOT statement is exactly the pullback of an old
statement through `f`. If so, return **`RESOURCE-REINDEXING-FIAT`**. This test does
not fire merely because two models simulate one another with overhead: it requires
unchanged computational objects/morphisms and transport of the entire proposed
theorem content through the same reindexing.

**C3 - antecedent-forcing test.** Require all of the following:

1. `A,O,P1,P2` were independently meaningful before the candidate boundary or
   ruler was named;
2. candidate-authored examples, benchmarks, applications, or narratives are not
   the sole evidence for `A`;
3. erasing the proposed admission/resource clause prevents a uniform preservation
   of at least one frozen observation, composition law, or theorem statement across
   `P1,P2`; and
4. that failure is not already explained solely by C1 or C2.

If any item fails, return **`BOUNDARY-FIAT`**. Passing C3 says only that the boundary
is forced; it does not establish novelty or a theorem.

**C4 - exact-scope occupation test.** Use the strongest translations in the
occupation packet. The occupation tokens are **FROZEN**:

- **`OCCUPIED-BOUNDARY`:** one pre-existing established model already states the
  exact antecedent-forced class contract, and a uniform definitionally conservative
  translation preserves the candidate's objects, morphisms, observations,
  composition, resource preorder up to the declared encoding equivalence, and
  theorem architecture at the claimed scope. Equality of extension sets, a
  robustness equivalence between non-isomorphic presentations, or simulation with
  arbitrary overhead is not sufficient.
- **`OCCUPIED-PRODUCT`:** the candidate is a generated product of established
  models and every proposed proof decomposes into their existing component
  theorems plus generic accounting, with no load-bearing cross-component lemma.
- **`OCCUPIED-CAN`:** the exact automatic positive construction already exists at
  the frozen scope.
- **`OCCUPIED-CANNOT`:** the exact non-tautological negative theorem already exists
  at the frozen scope.

`OCCUPIED-BOUNDARY` or `OCCUPIED-PRODUCT` kills the proposed new-class destination.
`OCCUPIED-CAN` or `OCCUPIED-CANNOT` kills a novelty-dependent theorem packet and
forces a strict-delta rewrite; it does not by itself erase an otherwise forced
class. Similar vocabulary, one-way simulation with arbitrary overhead, or separate
occupation of ingredients is insufficient for an occupation token. Exact source
absence is also insufficient for clearance.

**C5 - theorem-readiness and nontriviality test.** Require:

1. a finite uniform, automatic, useful CAN on a natural problem;
2. a CANNOT that is not "a machine lacking the admitted primitive cannot use it";
3. a valid theorem architecture from the input packet;
4. a robustness/equivalence target relating `P1,P2` without arbitrary resource
   distortion; and
5. a complete/canonical problem when the chosen architecture needs one.

Return `NO-AUTOMATIC-CAN`, `NO-LOAD-BEARING-CANNOT`, `CANNOT-FALSE`,
`PRESENTATION-RESOURCE-FIAT`, or `NO-THEOREM-ARCHITECTURE` when the corresponding
item fails. An internal conservation law, hierarchy/tradeoff, exact outer
characterization, noncomposition theorem, or robust containment may be a CANNOT;
an unresolved old-versus-new separation is not mandatory.

**C6 - positive admission return.** If C0-C5 produce no binding kill, return
**`CLASS-CHANGE`** and name the exact antecedent observation/composition/theorem that
forces the boundary. `CLASS-CHANGE` means only "legitimate class research boundary."
It does not mean novel, useful, theorem-proved, mission-achieved, or superior to
another class.

### 3.2 `COMPARE` procedure

Run P0-P5 in order for every comparative or beats claim. The order is **FROZEN**.

**P0 - freeze both sides.** Freeze the common task, interface, output, error,
uniformity, resource preorder and claimed region. Freeze each side's admitted
operations and charge acquisition, preprocessing, calibration, advice,
representation conversion, output materialization, and verification under one
common rule.

**P1 - symmetric common closure.** Close both sides under every task-preserving
operation declared common or free by the comparison. Do not withhold a common
compiler, representation, random source, controller, memory, or downstream
postprocessor from only one side. A defining primitive excluded by a frozen forced
class boundary is not silently gifted to the other class; the claim is then an
inter-class comparison and must say so explicitly.

**P2 - uniform compiler test.** If a uniform task-preserving compiler maps the
candidate pipeline into the comparator's P1 closure inside the frozen resource
region and error contract, return **`SAME-CLOSURE-ABSORPTION`**. This is binding even
when `CLASS` returned `CLASS-CHANGE` for some other internal claim.

**P3 - fiat and accounting tests.** If the comparative advantage is the pullback of
an old comparison through one resource reindexing, return
`RESOURCE-REINDEXING-FIAT`. If it depends on charging the same operation on one side
but declaring it free or unavailable on the other, return
`ASYMMETRIC-ACCOUNTING`. If either class boundary itself is unforced, inherit its
binding `CLASS` kill.

**P4 - occupation test.** If the exact comparison and resource region are already
an established theorem under a typed equivalence, return `OCCUPIED-COMPARE`. A
source-advertised empirical race without the frozen contract is not a theorem and
does not establish either occupation or advantage.

**P5 - live comparative return.** Only if P0-P4 survive may the claim return
`COMPARE-LIVE-PENDING-THEOREM`. This is permission to attempt the comparative
theorem, not evidence for it. No comparative claim is used to establish the class
boundary in C3.

## 8. Hostile self-audit of what `CONFIRM` does not establish

**HEURISTIC - NATURALNESS LIMIT.** Antecedent forcing is an auditable evidentiary
standard, not a decidable mathematical test of naturalness. A determined author may
still search for a friendly external practice after inventing a boundary. The
pre-vocabulary timestamp, independent presentations, and erasure witness make that
laundering harder and falsifiable; they cannot make taste mechanical.

**HEURISTIC - RETROSPECTION LIMIT.** Historical winners are tested with mature
theorem packets accumulated after founding. This shows that the gate does not erase
them now; it does not prove the exact same evidence would have been available on day
one. `CLASS-CHANGE` therefore remains admission to research, not a demand that the
entire mature theory pre-exist.

**HEURISTIC - OCCUPATION LIMIT.** Exact-contract occupation is source-sensitive.
Failure to locate a typed equivalence cannot issue novelty. A Gate-0 candidate still
needs primary-source closure and may die later even after `CLASS-CHANGE`.

**HEURISTIC - MISSION LIMIT.** A calibrated admission procedure cannot itself
supply a new class, useful automatic CAN, reviewed CANNOT, robustness theorem, or
public consequence. Treating `CONFIRM` as the mission result would violate both
