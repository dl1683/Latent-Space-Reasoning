## 0. Contract, rigor, and census boundary

This document asks a different question from the kill files. The kill files ask why
a proposed *new class* failed. This document asks what kind of theory already owned
the proposal, whether that theory already had its own 1936-like crystallization,
and—only where it did not—what structural obstruction prevented one.

The final correction in `PROGRAM.md` is binding: this is a **triangulation**, not a
unification program. The homes below are evidence about coordinates at which a new
model should or should not be built. Pass 3 must not turn them into instances of a
grand wrapper.

### Rigor labels

- **EMPIRICAL SOURCE FINDING** means a claim checked against the named primary
  literature and the repository's source-closed kill packet. It is not an
  experimental result.
- **HEURISTIC SCORE** means this analysis's judgment about whether an occupying
  formalism has the four winner properties. The cited theorem or definition may be
  proved; the mapping to the four-property rubric is still judgment.
- **HEURISTIC DIAGNOSIS** means a proposed reason for non-crystallization.
- **CONJECTURE** and **SPECULATION** are reserved for Pass 3.

No claim is promoted to `PROVED` here. The requested product is a source-backed
diagnosis and either a precommitted Gate-0 registration or a hard source-bound
return showing why no registration is honest. The independent Batch-17 audit made
the latter binding for the attempted construction.

### Four-property code

For every row, the score has the form `R/I/E/Q`:

1. `R`: a previously free or hidden resource is first-class;
2. `I`: a genuine impossibility/lower-bound theorem exists;
3. `E`: equivalence, invariance, or robustness theorems stabilize the definition;
4. `Q`: the formalism makes a famous, pre-existing question crisp.

`H` = **HAS** at the stated scope; `P` = **PARTIAL**; `L` = **LACKS**. A score is
never obtained by silently unioning unrelated theories. When several homes jointly
absorbed a candidate, the cell names which home supplies which property.

### The exact mathematical object

**SPECULATION — DEFINITION DRAFT.** A finite CfAC instance is

\[
  X=(D,\Theta,\theta^\star,I,O,H,\tau_0).
\]

The fields are:

1. \(D=(V,E,\{M_v\}_{v\in V})\) is a finite typed diagram. Each \(M_v\) is a fully
   revealed deterministic finite-state input/output transducer. Ports, alphabets,
   state sets, transition maps, and local initial states are finite.
2. \(\Theta\) is a finite, explicitly generated set of well-typed **composition
   completions**. A completion fixes the hidden wiring/synchronization maps on
   \(E\). Membership and application of a displayed completion are decidable.
3. Nature fixes one \(\theta^\star\in\Theta\), not revealed to the machine. This is
   finite hidden input, not advice: the generator emits \(\Theta\), and the access
   protocol is the only way to learn which completion is live.
4. \(I,O\) are finite public intervention and observation alphabets. Observation is
   of public I/O only; local hidden states and the wiring map are not readable.
5. \(H\) is a finite deterministic monitor specifying the candidate-independent
   relational task contract over possible public continuations.
6. \(\tau_0\) is the common public initial checkpoint. A live branch is a
   noncopyable handle to one execution of \(D_{\theta^\star}\) from a public
   checkpoint.

A computation is an ordinary uniform RAM/TM controller plus live-branch handles. It
may:

- perform charged ordinary finite computation;
- apply a public intervention to one live handle and observe the finite response;
- retain or discard that evolved handle;
- request an independent continuation from the same public checkpoint **only when
  the access contract grants another counterfactual branch**;
- combine transcripts in ordinary memory; and
- return an answer with a finite, mechanically checkable certificate whose
  soundness ranges over all completions consistent with the transcript.

It may not inspect \(\theta^\star\), rewind a handle, copy hidden state, synthesize a
new live handle by simulating one guessed completion, or treat a model-checker over
\(\Theta\) as evidence of which completion is physically live.

### Native restriction and resource

**SPECULATION.** The intrinsic resource is **counterfactual access rank**
\(\operatorname{car}(\pi)\): the maximum number of pairwise
intervention-incompatible live continuations in execution tree \(\pi\) that descend
from the same public checkpoint and share the same fixed
\(\theta^\star\). The restriction class \(\mathcal C_k\) contains exactly the
uniform semantic procedures with \(\operatorname{car}\le k\).

The full resource vector is

\[
  R(\pi)=(\operatorname{car}(\pi),q(\pi),t(\pi),s(\pi),c(\pi)),
\]

where \(q\) is public interventions/observations, \(t\) ordinary steps, \(s\) space,
and \(c\) certificate length. The preorder is coordinatewise, with explicit
polynomial presentation overhead only where the two representation compilers prove
it. CfAC does not make ordinary compute, certificates, or representation changes
free.

**HEURISTIC DESIGN JUSTIFICATION.** \(\operatorname{car}\) is intended to count an
access topology, not specimens or emitted bits. Serializing two incompatible
continuations into one “mega-observation” changes the public interface and must be
charged as a representation translation. Whether this survives the C1–C3
nonfiat/reindex tests is an open obligation, not a settled fact.

### Antecedent and famous question

**EMPIRICAL SOURCE FINDING.** Integration testing, live control, system
identification, and black-box verification all study systems whose internal model
or interconnection is incomplete. Active automata learning commonly assumes
membership/equivalence queries and resets [S30–S31]; non-resettable Mealy inference
has been studied from a single trace [S41]; network reconstruction studies known
dynamics with unknown topology and proves identifiability limits [S42]; safe
learning studies information-gathering while every compatible dynamics must remain
safe [S43]; hyperproperty monitoring studies what multiple or single executions can
certify [S44].

**HEURISTIC ANTECEDENT.** These facts establish a natural pre-candidate question,
not CfAC novelty:

> **How many genuinely alternative executions of one live composed system are
> necessary before correctness of the whole can be certified from fully understood
> parts?**

**HEURISTIC — TWO PRESENTATIONS.**

- P_port: explicit local transition tables, typed port graph, completion set, and
  public transcript tree;
- P_behavior: bisimulation-minimized local behaviors, renamed ports, a finite
  relation of admissible global traces, and the corresponding prefix tree.

The robustness target is a pair of uniform charged compilers preserving public
trace sets, completion consistency, certificate semantics, and

polynomial. If such compilers do not exist, PRESENTATION-RESOURCE-FIAT fires.
