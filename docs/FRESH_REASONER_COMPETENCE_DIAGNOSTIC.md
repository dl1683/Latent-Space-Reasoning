## Qualify the ordinary receiver on fresh cases

The latest upstream v2 matched scripted route finishes seven calls with
6,585 input and 622 output tokens including EOS, six searches and six
reads (203 verified bytes) in each adapter. This is a useful feasibility
result, not generated competence. Do not add a further host layer to
answer a question about learned behavior.

Use independently authored fresh cases with direct support and composition
(the existing eight-task visible calibration matrix supplies coverage
guidance). Freeze acceptable obligation decompositions, source pins,
sufficient and defeating spans, and verdicts independently; accept valid
paraphrases and alternative support sets. Keep gold away from the reader
and worker. Include a distinct side fact, wrong-entity alternative,
unresolved premise and revision/history. Generate short evidence-need
declarations and separately gradeable findings with citations, without
prewritten answer candidates. Record the declared needs before findings.
For each gold obligation, report the joint counts of (inferred/not inferred)
x (correctly answered/not correctly answered). Score both independently.
A correct conclusion can be produced despite an incomplete declared plan;
a correct plan is not a correct answer. Separately score semantic correctness,
support-chain sufficiency, authentic bytes/pins, unsupported extras,
false closure and termination. A valid receipt is not entailment.

For a separately authorized diagnostic, use three fresh sessions per task:

| Arm | Input on the same complete pinned corpus |
|---|---|
| U | Broad task only; generate needs and findings |
| N | Same task plus neutral obligation list; no answers, source IDs or joins |
| E | Same N plus marked relevant verbatim spans, including defeats; no composed conclusion |

Keep the model, template, output contract, decode policy and finite budgets
fixed; account for all input deltas. Mark spans in source order, not proof
order, and preserve the actual coverage boundary for unresolved claims.
The extra inputs are explicit diagnostic assistance, not fair headline
comparators. Preselect the arms, randomize order across stateless sessions,
and judge findings blind to arm. At most eight tasks (four direct, four
composed) times three sessions is a proposed 24-session cap, not an
allocation. If a budget or parser refuses, report the failure separately;
do not hide it as semantic incorrectness or tune on the same cases.

Interpret U fail/N pass as a reason to prioritize requirement inference;
U and N fail/E pass as a reason to investigate evidence access/binding;
E fail on direct support as a failed receiver/answer-interface prerequisite;
E pass direct but fail composition as a reason to examine composition.
If a recorded correct set of premises precedes a wrong conclusion, that
is an observable composition/readout error. If a correct generated finding
is lost from the required final output, that is a rendering/termination
failure. These interventions do not prove private cognitive mechanisms;
mixed or nonmonotonic patterns stay unresolved. Do not condition the main
denominator on successful plans. Only unassisted, supported U answers
qualify ordinary competence. Retain the existing registered gates.

## The next experiment should require a new input, not a stored answer

Freeze a changing mixed-modality corpus and a source-only worker policy
before task selection. A worker should discover a reusable operation
F, another check it against a subsequent source event, publish it with
pins and invalidation conditions, and exit. A fresh reader reopens that
publication. The late evaluator chooses at least two distinct input tuples
x1 and x2, whose selection is independent of the worker's proposals and
hidden from it until after publication. The input binding x2 must not be
a repeated worker query or a precomputed terminal lookup. Choose an
input whose expected consequence genuinely requires composing the acquired
relation with a fresh binding, not merely pointing to a stored destination.
Include a no-op/irrelevant input control. An independently specified
exact interpreter adjudicates F(x1), F(x2), changed-pin outcomes and
unresolved cases; do not score a question whose answer is in the acquisition
prompt. The source-only corpus may contain the premises: no task or gold
is needed to maintain them. Keep the evaluator's candidate family frozen;
record the worker's own proposal and checked scope before late selection.
If it acquires nothing, that is a failure, not permission to select a
more favorable operation.

On identical source schedules compare final-state and one fixed interior
layer; freeze layer, gains and binary ingress on disjoint calibration
sources. Each architecture must own its own compatible publication;
do not equate a cross-layer transplant with changing only an address.
Within each layer, compare the intact value with a key-only source-address
control (same value/pins/competitors), same-pin operation removal,
restoration and the same reasoner with memory omitted. Record target
selection/ambiguity, actual applied values, and every subsequent ordinary
and derived selection separately from late answer quality. For a separately
reported mechanism diagnostic, hold later ordinary source inputs fixed
across same-pin removal/restoration or donor substitution where the prefix,
initial selection and input tensors match. The upstream sealed interior
donor control does this for supplied circuits. A surviving donor effect
only excludes new ordinary suffix observations on that run; earlier
state and later derived selections can still carry the consequence.
Do not use clamped diagnostic receipts for citations.

A warm exact interpreter gets the same source-only build, caching,
materialization and revision rights, and a competent source-aware text
reader gets equivalent evidence access. Include revision of one required
premise, withdrawal and restoration, historical reads and an unrelated
region. Charge acquisition (including rejected proposals), storage,
revision, verification, restart, readout and fallback. An interior
injection still costs a full forward. Compare full-life costs at matched
supported quality, not query-only time or the number of positive
similarities.

**Stop/continue:** The useful outcome is independently supported generated
answers on both new inputs, a source-only operation that predicts their
consequences, loss and restoration of that contribution at the same pin,
correct revision and history, and a cost/quality result against warm exact
and text controls. A same-pin effect on one previously seen input, a
scripted route, or a correct cached answer is insufficient. If the text
receiver cannot handle ordinary composition on the selected family, first
qualify it; do not use its failure as a latent advantage. If the exact
interpreter matches or wins, preserve the narrower finding and reconsider
the mechanism rather than scale it. This is the next scientific gate, not
a requirement to build more deterministic fixtures.

## Reproduce archived audit

Executed against the exact fetched four frozen JSON artifacts at the
reviewed head. This is a static check without model weights. Node.js 18+,
run from repository root:

```js
function audit(tasks,gold,record,score) {
  const check=(x,m)=>{if(!x) throw Error(m);};
  const rows=tasks.tasks.map(t=>{
    const o=[...t.task.matchAll(/^([123])\. (.+)$/gm)].map(m=>[m[1],m[2].split(/(?<=\.) /)]);
    check(o.map(x=>x[0]).join("")==="123","labels");
    const [a,b,c]=o.map(x=>x[1]);
    check(a.length===7 && b.length===7 && c.length===5,"sentences");
    check(a.at(-1)===b.at(-1)&&b.at(-1)===c.at(-1),"citation list");
    return {task:t.task_id,expected:gold.answers[t.task_id],different:a.flatMap((s,i)=>s===b[i]?[]:[i+1])};
  });
  check(JSON.stringify(rows.map(x=>x.different))===JSON.stringify([[1,4],[1,4,5],[1,4]]),"sentence contrasts");
  check(record.task_id===score.task_id&&record.pin===score.pin,"record identity");
  check(record.prediction==="1"&&score.prediction==="1"&&score.expected==="2"&&gold.answers[record.task_id]==="2"&&score.correct===false,"outcome");
  check(record.terminated===true&&record.output_token_ids.length===2,"label/EOS");
  check(record.delivered_source_ids.length===5&&gold.critical_source_ids.every(s=>record.delivered_source_ids.includes(s)),"sources");
  check(record.input_tokens===784&&record.input_tokens===record.prompt_token_ids.length,"token count");
  return rows;
}
```
