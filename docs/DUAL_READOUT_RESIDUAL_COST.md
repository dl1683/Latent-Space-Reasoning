# Learn the residual work, not just the representation

27 November 2026. Base 9281e393. Classification: mathematical foundation and an ordinary exact competitor on real corpus-derived readouts. Not a learned language result, not a receiver extension, and not an authorization or modification of the frozen gate.

## Decision: a dual-space maintenance policy

The prior codec study found that preserving a cheap-to-rediscover equivalence was of little value against adaptive cold. Move from choosing which source states to retain to choosing which **future computations can be reconstructed from a combination of retained computations and a small, exactly identified residual**. A worker should estimate the cost of recovering a missing distinction, not merely its current predictive error, frequency or embedding novelty. Do not infer semantic equivalence just because the residual vanishes on current questions.

This connects to established systematic linear data structures and matrix rigidity ([Ramamoorthy and Rashtchian, ITCS 2020](https://arxiv.org/abs/1910.11921)) and ordinary aggregate-view selection and rewrite ([Oracle query rewrite documentation](https://docs.oracle.com/en/database/oracle/oracle-database/19/dwhsg/basic-query-rewrite-materialized-views.html)). The algebra below is not a new theorem about all latent systems; these are serious exact baselines. Database engines can already decide whether part of a query is answerable from a materialized view. Our target is learning the meaning of the operations and how to bind them to heterogeneous corpus evidence without supplied schemas, including when a later revision changes which evidence matters.

## Exact boundary

Let x be an unrestricted vector in F^n over a field F. An opening representation retains y=A x, with A fixed independently of x for the declared setting. A future scalar readout arrives as a covector q. The reader may reopen raw coordinates x_i at a cost.

For a set J of reopened coordinates, exact determination of q.x for every x is possible iff q is in row(A)+span{e_j:j in J}. Sufficiency: find coefficients a and residual r with q=A^T a+r, support(r) contained in J; return a.y+r.x. Necessity: otherwise there is a vector h in the kernel of the stacked observation matrix (A; e_j^T) with q.h nonzero. x and x+h are indistinguishable on all observations and have different answers. The same necessity applies on every terminating trace of a deterministic adaptive exact reader: perturbing x by h leaves all observed values unchanged and hence preserves that entire adaptive trace. This argument is over unrestricted field vectors, not a domain with known additional constraints, and assumes exact arithmetic.

Thus the minimum number of reopened coordinates is min_a ||q-A^T a||_0. For weighted reads, replace support cardinality by the sum of source costs. This is a distance-to-row-space problem, not nearest-neighbor similarity. Existence of a good sparse decomposition does not imply that finding it is cheap. A learned proposal should be challenged against a coefficient-domain certificate; quantization and noisy estimates need explicit residual bounds. For linear queries over finite fields, this is also a coding/covering problem. For general semantic or nonlinear operations, the formula does not establish a certificate.

Revision: if x changes by a known delta, update y by A delta. A correction that changes A, the coordinate semantics, source identity, or readout family is a different event; validate the new interpretation or reopen the requisite evidence. An ID-only withdrawal needs the old value and origin-specific information. A signed decomposition is not a citation by itself; receipts must retain the support of every used row, residual source pin, coefficients and all dependency versions. Dense views can induce substantial update fanout and provenance costs even when their readout saves reopening.

## Executed ordinary comparator

Used the actual local Debian installed-package metadata (dpkg-query), not a generated dependency graph. Snapshot SHA-256 a178e58948b49017a191d23fc9c24b8089e420dcbc2b18b74c8ed48ab29dadc7; 1,398 installed package records with Installed-Size. Query masks are the set of installed base package names mentioned in Depends/Pre-Depends (one or two hops), and unions/differences of two held roots. All named alternatives and architecture variants are included, versions ignored; this is explicitly a reference-name graph, NOT a dependency resolver or actual marginal installation footprint. Readout is sum of the reported KiB values for the mask. Query masks and source IDs are given to all arms; discovering their meaning is NOT tested. This is a known-address linear control only.

Train roots by SHA-256(name) mod 4 != 0: 1,055; held roots: 343. Nonempty training masks: 1,666 occurrences, 1,145 distinct. Held panel: 275 direct, 275 two-hop, 478 union, 344 difference masks (500 deterministic held-root pairs, dropping empties). Separate novelty subset has 378 union and 282 difference occurrences absent from the training masks; these are subsets, not extra independent trials. Same underlying corpus, no unseen-corpus claim.

At each budget compare frequency-ranked coordinate cache, greedy materialized aggregate cache, and fixed half-budget coordinate/aggregate hybrid. Storage model per retained row: 8-byte exact sum, 2-byte member count, 2 bytes per source index. All arms use same row format; coordinate cache could be implemented with less overhead. This is a theoretical compact payload accounting, NOT measured Python memory, bytes on disk or end-to-end cost. The graph, source register, query generation and raw value archive are shared and excluded. Aggregate selection greedily maximizes marginal one-view training read reduction per byte. Late query rewrites use the best single view and optionally one further signed greedy view, then read every residual coordinate not retained. Exact sums independently recomputed from the full source array and checked on every query. The two-view reader is a stronger local heuristic, not optimal sparse decomposition or an optimized commercial DB.

At 1,024 bytes hybrid uses 1,022 bytes, 42 coordinates and 15 views. Coordinate uses 1,020 bytes and 85 coordinates. Hybrid saves 523 reads (7.2%) on the held panel; for the strictly novel composed-mask subset it saves 371 reads (5,041 vs 5,412). At 4,096 bytes hybrid needs 790 MORE reads than coordinate-only (26.1%). Aggregate-only loses at all three tested ceilings. These are exploratory choices and masks, not a population-rate estimate.

Revision stress: same 100 randomly selected source values incremented by 1 KiB, fixed query masks. Checked the exact delta formula for every materialized view and repeated readout equality with recomputed revised values. The 1,024-byte hybrid needs 21 affected-row updates versus 7 for coordinate-only; 4,096-byte hybrid needs 77 vs 28. These are logical update events, not measured runtime or a live revision implementation. Historical pin maintenance, graph changes, index traversal, proposal cost and physical transport are not timed. Even the modest 1,024-byte reopening benefit is not an economic win until all of those are charged.

## Architectural consequence and next move

A pure aggregate or operator store can be worse than a small well-selected source cache, even when it fits opening readouts substantially better. Use a mixed representation only when learned reusable computations pay for their admission, addressing, residual reopening and invalidation. Maintain query-blind candidate operators and exact source-linked residuals; propose new operators from source-native prediction tasks rather than supplied future prompts. A prospective learner should predict both the operation and the unresolved residual on independently sampled future edit/readout families, with the witness deriving the residual independently (not granting the learner the mask). Charge failures to discover relevant operands and compare against an equally budgeted adaptive exact materializer, coordinate retention, and ordinary text/KV. Include a no-memory arm and same-pin operation removal/restoration. Compare net lifecycle value, not reconstruction score or an oracle-given mask. The above conventional control provides the cost target and a failure case, not evidence that the proposed learned system meets it.

The four-case independent reader gate remains unrun and frozen; no held inputs, grader, pretrained model, or execution authority touched. Local memory ceiling remains 4 GiB versus the 12 GiB registered floor. This is a parallel mathematical/design contribution; do not invest in further engineered view heuristics here. Next highest-leverage work is a query-blind learned semantic operation/readout pilot on independently authored source and rule revisions with a competent ordinary control, following the gate.
