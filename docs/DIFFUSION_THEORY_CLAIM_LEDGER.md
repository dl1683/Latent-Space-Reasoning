# Diffusion Theory Claim Ledger

This ledger keeps the mathematical theory honest. It maps each theory claim to
its current evidence, assumptions, falsifiers, and next proof obligation.

Status meanings:

- `validated-local`: supported by current generated artifacts and fresh CUDA or
  deterministic validation in this repo.
- `supported-conditional`: mathematically coherent and supported by local
  evidence, but conditional on the current abstraction or task slice.
- `hypothesis`: plausible direction that still needs broader evidence.
- `boundary`: negative or cautionary result that limits the claim.

## Current Strongest Theory Statement

The strongest statement the repo can currently defend is:

Diffusion-native latent reasoning improves the current lean GPU mixed benchmark
when a verifier-visible failure appears in an editable denoise trajectory, a
cost-aware selector estimates that repair is worth the extra generation, and the
repair preserves stable task constraints.

This is stronger than "we sampled more" and narrower than "general reasoning is
solved."

## Open Proof Obligations

1. Equal-cost AR rewrite baseline: compare diffusion repair to an
   autoregressive rewrite system with the same verifier spans, judge access, and
   generation budget.
2. Transfer slice: test whether `first_repairable_step`, `prompt_gap_count`,
   `source_quality`, `source_task - selected_task`, retention loss, and realization loss
   predict marginal repair value outside the current eight planning tasks.
3. Information-channel accounting: every promoted theory claim should state
   what came from prompt, model, denoise state, verifier, judge, and anchor.
4. Retention reporting: every new repair operator should report whether it
   preserves prompt terms, digits, roles, target spans, and compact controls.
5. Learned selector: replace fixed thresholds with a small predictor trained on
   generated marginal-value targets, then evaluate on held-out tasks.
6. Decomposed proof object: train availability, promotion-value, source-trust,
   retention, and cost heads, then test whether the combined error function
   beats a single repairability scorer on fresh GPU slices.

## How To Update This Ledger

When a new theory claim is added:

1. Add it as a row with a conservative status.
2. Link to score/report/audit artifacts, not only prose.
3. State what would falsify it.
4. Add the next proof obligation as an executable benchmark or audit.
5. Promote the status only after generated artifacts and validators support it.
6. Run `python experiments\validate_diffusion_theory_claim_ledger.py` before treating the ledger as public-current.
