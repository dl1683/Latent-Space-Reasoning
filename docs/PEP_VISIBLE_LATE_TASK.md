# PEP visible late-task calibration (26 November 2026)

Classification: evaluation infrastructure necessary for mission progress, not a reasoning result. In response to issue #6 comments 7197504163 and 7197976405, this freezes a source-disjoint public calibration workload and a manually adjudicated oracle before the proposed learned worker or reader is implemented. The source authors are independent of LSR; the task author did not implement the acquisition/recurrent reader for this workload. Only one semantic annotator has checked this oracle so far. It is visible development data, not the held panel and not permission to resume paused model runs.

## Source and revision contract

Use python/peps, the exact parent and child commits in the sibling JSON. Enumerate all regular Git blobs matching peps/pep-NNNN.rst (four digits). The complete declared universe is 655 proposal documents per pin, about 12 MB of source bytes. No executable code, Git history/commit messages, generated website, ancillary assets, external links, or gold in the worker or reader mounts. The controller can use Git to acquire the corpus but exposes only (opaque document ID, UTF-8 source bytes, blob digest, generation) and a manifest of declared scope. Keep document-internal PEP identifiers and references: do not provide a special PEP-number-to-latent-axis map or gold relations. Revision events deliver changed document bytes plus explicit additions/deletions if any. The manifest and source identity are generic, not task-conditioned.

The actual 2024-09-26 change edits only PEP 749 in this scope; 654 source blobs remain identical. No source is added/removed. Publish opening and revised snapshots before releasing tasks. Reattach the opening snapshot after the revision and optionally republish the old bytes as a new generation to distinguish historical read from restoration. The proposed spec is a draft supplement to the accepted PEP 649, not a description of a running interpreter. In particular the changed draft retains SOURCE examples after explicitly renaming the format to STRING. The opening draft proposes an override of assignment behavior; the revised draft drops that override and adds an explicit deletion rule. A simple bag of mentions or latest-document-wins rule cannot distinguish governing clauses from residual examples. The underlying generics PEPs 695 and 696 and independent exception-group PEP 654 are unchanged.

## Frozen late interface

- Controller (only trusted holder of the public calibration oracle): delivers source snapshots to query-blind publisher, then waits for publisher exit and seals state plus encoder, program and environment hashes. Source manifest, candidate disclosures, and all proposals/coverage receipts are retained, including rejected work.
- Publisher: receives no question, target IDs, labels, answer spans, task order or example-specific heuristics. It may emit generic predicted relations, scopes, conflicting alternatives, uncertainty, provenance, and installed operations. Record what regions were not processed. The same generic input interface applies to every arm. No task authoring from publication outputs.
- Reader: receives a pinned publication and only a task's raw natural-language string. The late task file must not include obligation IDs, PEP numbers from the oracle, target directions or witness coordinates. No source checkout or grader mount; exact source reopening only by charged controller service under the declared pin. Freeze a generic task encoder/decoder and no model training on this public calibration. Freeze roster before execution; controller randomizes task order independently after publication. Both tasks run at both pins, plus historical read, with fresh readers.
- Grader: receives immutable pre-checker proposal and task/pin only after read completion. Grade semantic obligations, contrary evidence and exact blob-scoped witness spans; never replace or supplement proposal. The JSON evidence entries are evaluator-only examples of acceptable witnesses, not exhaustive evidence sets. Stable witnesses may be cited at either pin if the blob is identical. Recompute byte offsets from raw Git blobs (line anchors here are not byte receipts). Distinct line spans in one file are one origin. Record equivalent decompositions separately, not a strict lexical match.
- Custody: extend the existing stage-isolated journal harness. Build an explicit minimal runtime allowlist, excluding this document, its JSON, tests containing these answers, the PEP source corpus, and Git metadata. Compare runtime mount file digests to all source blobs and reject overlap; also check packaged source copies/embedded fixtures manually. Mount only controller-provided question in the reader. Public calibration gold is not genuinely secret from pretraining or an untrusted implementation; repeat with independently held tasks before drawing scientific conclusions.

## Matched arms and falsification

1. Maintained latent state + same recurrent core, with generic source-derived proposals.
2. Equal-information warm incremental exact join: receives identical *predicted* relations, candidate scopes, alternatives, provenance, source changes, authority information, and maintenance budget. It may index, materialize or cache any reusable consequences and do incremental invalidation. No gold. Include same reader/model budget and charge all extraction costs.
3. Warm text agent with all original source bytes, full-text indexing, caching, reranking and iterative reading allowed under the same model, source-read, delivered-token and wall/compute allowances. It must receive the same pin and be able to reopen old bytes.
4. Memory-omitted same core (no world-supplied address map). Separately do same-pin operator-off/restore while preserving ordinary observations, plus reachable donor intervention if a genuine hidden transition is claimed.

Compare all critical obligations per task, correct conflict acknowledgment, false closure (including unsupported exactness and invented API completeness), wrong-pin assertions and exact provenance. Side obligation must stay correct. Log every encoder invocation/source byte, build/update/repair wall and CPU time, peak RSS, persistent bytes, proposal cost, reader cost, cache reuse, source openings, fallback and grading separately. Report opening build and subsequent revisions, repeated warm reads and historical reads separately, not only one favorable amortized workload. No claim of superiority unless the full end-to-end comparison earns it; a correct warm join is a valid negative result. Missing learned acquisition or reader support, or a source- or answer-leaking mount, is a failed/incomplete instrument, not a zero-scored baseline.

## Verification performed

GitHub's raw tree listing for both pinned commits was nontruncated. Counts, byte sizes, and the single changed blob were computed from those listings. Both pinned texts were fetched independently of LSR, all 17 oracle line ranges were checked for their expected anchors and exact Git blob IDs, and four unchanged evidence documents were fetched at both pins and compared for text and blob identity. This verifies source selection and witness anchors, not automated semantic adjudication, byte offsets, model execution, whole-corpus reasoning, runtime isolation on this corpus, or lifecycle economics. The oracle still needs an independent second annotator and integration into the real publisher/reader. No model run or held evaluation was performed. Local Git network access is unavailable in this execution environment.

The high-value next gate is a source-only maintenance publication followed by raw-text late questions with no gold target mappings. Do not create another deterministic dictionary that directly encodes these specific answers. First obtain an independently reviewed oracle, then use the same source-derived predictions in the latent and warm exact arms. A positive result must depend on the maintained computation and survive the matched baselines.

The current `repository_transport_control` publication is a Python-import
control, not the PEP loader: it uses AST imports as its observation grammar,
limits changed source bytes to 8 MiB per revision, and `open_task_world`
rejects an active index above 8 MiB. This calibration has 12,061,646 source
bytes at its opening pin. Do not raise those limits without a resource
preflight. Build a generic raw-document handoff with opaque document IDs,
measure index memory and setup/read costs on the full 655-document snapshot,
and keep PEP identifiers and oracle mappings out of latent coordinates and
reader metadata. `TaskWorld` currently adds source identifiers to its lexical
index text, so this loader must use truly opaque IDs rather than PEP filenames
or numbers; preserve PEP references only in the source text itself.
