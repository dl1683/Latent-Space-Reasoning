**Bottom Line**
Section 13 is directionally right, but I would sharpen the language: this is not a full tautology; it is an extractor-conditioned selection effect. EOS does not mechanically imply correctness, but EOS strongly changes what the last-integer extractor is measuring.

For completed traces, last-integer is usually a final-answer parser. For truncated traces, it is a tail-of-working parser. That makes `P(correct|EOS)=1.0` real as an observed result, but unsafe as a universal mechanism claim.

**4. Repetition Penalty Confound**
Yes, include a `repetition_penalty=1.0` control.

This is more serious than “it is applied to all operators.” Because prefix uses `inputs_embeds`, while greedy/temperature usually use `input_ids`, the repetition-penalty processor may not see the same prompt-token history across operators. That can make the operators non-equivalent even before considering the perturbation.

Possible effects:

- It can suppress repeated arithmetic tokens, repeated digits, and repeated verification phrases.
- It can either reduce exact loops or create semantic wandering by penalizing natural next tokens.
- It can interact with temperature because sampling from already penalty-shaped logits is not the same as sampling from the base distribution.
- It can interact with prefix because different early generated tokens define a different penalty history.

Minimal control:

- Greedy at `1024` and `2048`, `rp=1.0` vs `1.2`.
- Prefix N=10 at `1024`, `rp=1.0` vs `1.2`.
- Temp0.6 at `1024`, `rp=1.0` vs `1.2`.

If this changes EOS rate materially, all claims become conditional on `repetition_penalty=1.2`.

**5. Priority Directive**
The single biggest remaining blind spot is generation-path equivalence.

Before Phase 1A, build one instrumented generation wrapper that makes prefix, greedy, and temperature comparable: verified generation boundary, true generated-token count, full raw output, EOS/length stop, same repetition-penalty semantics, and identical extraction inputs. Right now, `inputs_embeds` vs `input_ids` can affect token accounting and possibly repetition-penalty history. If that is not nailed down, the EOS mechanism, compute Pareto curves, and repetition-penalty control all rest on unstable measurement.
