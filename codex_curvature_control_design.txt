## Runner specification

### 1. Static preflight before model loading

The runner should load only the pinned tokenizer first.

For every expanded context and surface, assert:

- Every semantic, neutral, and `NONE5` surface is exactly five tokens.
- `encode(surface + query) == encode(surface) + encode(query)`.
- `delta = len(depth4_prefix) - len(depth3_prefix)` is positive.
- Each generated padding string tokenizes to exactly `delta`.
- `d3_prefix_tokens + padding_tokens == d4_prefix_tokens`.
- Therefore suffix starts agree exactly.
- Since every surface is five tokens, query starts also agree exactly.
- Expected calls equal 768 and do not exceed 800.

Verified padding forms:

- For `delta=21`:
  - `PAD_BARE`: 21 repetitions of `"#\n"`.
  - `PAD_WORD`: seven repetitions of `"# pad\n"`.
- For `delta=23`:
  - `PAD_BARE`: 23 repetitions of `"#\n"`.
  - `PAD_WORD`: seven repetitions of `"# pad\n"` followed by two `"#\n"` lines.

Any mismatch returns `FAIL_INVALID_DESIGN_NO_MODEL_RUN`.

Resolve the pinned snapshot locally and pass its absolute snapshot path to an unchanged `ModelAdapter`:

### 3. Collection order

There are 12 prompt contexts:

\[
6\ \text{templates}\times2\ \text{literal profiles}.
\]

For each context:

1. Build and cache the d3 prefix.
2. Evaluate all 15 arms under:
   - `D3_RAW`
   - `D3_MATCH_BARE`
   - `D3_MATCH_WORD`
3. Run any selected d3 replay calls before deleting the state.
4. Delete the state and collect garbage.
5. Build and cache the d4 prefix.
6. Evaluate all 15 arms under `D4_NATURAL`.
7. Run selected d4 replays.
8. Delete the state, checkpoint atomically, and check wall/call caps.

Each observation must store:

```text
template_id, template_family, template_split
literal_profile
depth, placement, padding_family
prefix_tokens, padding_tokens, suffix_tokens
suffix_start, query_start
surface_id, surface_role, surface_pair_id, surface_split
dist[11]
top_digit
call_index
is_replay
```

The call budget is:

\[
12\times(2\ \text{prefix calls}+4\times15\ \text{continuations})
+24\ \text{replays}=768.
\]

### 4. Primary estimands

For each stored distribution and each offline shadow digit \(q\in\{8,9\}\):

\[
z_q=\log p(4)-\log p(q).
\]

Use a floor of `1e-30` only for numerical safety.

At every placement, compare semantic arms against the position-matched `NONE5`:

\[
E_s=z_s-z_{\text{NONE5}}.
\]

For each padding family:

\[
\rho_A=E_A(d4)-E_A(d3_{\mathrm{matched}}),
\]

\[
\rho_M=E_M(d4)-E_M(d3_{\mathrm{matched}}),
\]

\[
\kappa_{\mathrm{iso}}=\rho_M-\rho_A.
\]

Report \(\rho_A\) and \(\rho_M\) separately even when the overall gate fails.

### 5. Position-gain null

For each padding family \(j\) and shadow digit \(q\), fit:

\[
E^{d3,\mathrm{matched}}_{s}
=\alpha_{j,q}+g_{j,q}E^{d3,\mathrm{raw}}_{s}+\epsilon.
\]

Fit only on:

- `short_names` train templates;
- the two train semantic-pair families;
- `N_NOTE`, `N_READ`, and `N_CHECK`.

Do not fit on any holdout template, holdout semantic pair, or `N_COMMENT`.

First validate the frozen mapping on `N_COMMENT` under all holdout templates. If the neutral effect range is too narrow or validation exceeds the registered error limits, G4 fails. Null failure must never count as evidence for curvature.

For each held-out semantic surface, predict:

\[
\widehat E^{d4\text{-position}}_s
=\alpha_{j,q}+g_{j,q}E^{d3,\mathrm{raw}}_s.
\]

Then:

\[
R_s=E^{d4}_s-\widehat E^{d4\text{-position}}_s
\]

and

\[
\kappa_{\mathrm{gain}}=R_M-R_A.
\]

### 6. Holdout and clustering

Nothing claim-bearing may use train templates or train suffix families.

The primary table has:

\[
4\ \text{held-out templates}\times
3\ \text{held-out suffix pairs}=12\ \text{blocks}.
\]

Within each block, average over:

- two inner-literal profiles;
- both offline shadow digits;
- both padding families.

Do not treat those nested rows as independent.

For confidence intervals, independently resample template IDs and suffix-pair IDs with replacement and take the resulting Cartesian block table. Use 100,000 replicates with seed `42017`. For `kappa_gain`, refit the nuisance gain model inside every bootstrap replicate.

Also report:

- eight individual block values;
- every template marginal;
- every suffix-family marginal;
- both padding marginals;
- both shadow-digit marginals;
- both literal-profile marginals.

The config actually produces **12** primary blocks, not eight: four templates × three held-out suffix pairs.

### 7. Verdict order

Evaluate gates in order and retain the first failure:

1. `G0`: token and budget validity.
2. `G1`: task competence under `NONE5`.
3. `G2`: ASSERT/MISLEAD positive control.
4. `G3`: replay noise and SNR.
5. `G4`: position-gain null identifiability and held-out validation.
6. `G5`: matched-position curvature.
7. `G6`: survival after position-gain subtraction.

`PASS_CONTROLLED_CURVATURE` requires every gate.

The new 0.15-nat threshold is prospective and has two rationales:

- it retains at least half of the original 0.284-nat estimate;
- its odds multiplier is approximately `exp(0.15)=1.16`, large enough to distinguish from the ±0.05-nat practical-null band.

The old 0.5-nat threshold must still be reported as a diagnostic; it is not silently replaced.

A PASS licenses only a controlled behavioral interaction. It still does not establish native geometry, quotient congruence, a phase transition, or a hidden-state mechanism.
